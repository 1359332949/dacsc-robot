## 不能由一次重跑解决的部分

原记录 13721：每个 suite、每个因素把候选按 `random.Random(hash((tag,s)) % 10000)` 洗牌取前 30。13724 报出每个因素四套件合计 120 条；13729 将名单分成 `<tag>_libero_<suite>.txt`，启动带 `--cond-align` 的方法运行；13782 有按因素的汇总。策略 seed 7 不是选择器有效种子，没有找到可验证的该进程哈希盐、实际有效种子或六份目标组合的完整有序清单。在本地工作区、当前 `/hy-tmp` 和检查过的仓库/证据备份未找到原 manifest 或可直接恢复清单的逐例 sweep 目录；不能断言外部备份也不存在。

对 Spatial 与 Object 三个因素各自枚举可能的有效种子（取值 0–9999，联合覆盖所有 ID 即提前停止）。在没有额外历史约束时，Spatial 的 292/258/351 个组分别都出现在至少一种可能选择中。**并非所有组都实际跑过；只是不知道是哪 30 条。** 不用今天的哈希盐或当年的聚合胜率反搜“看起来吻合”的名单。即使找回 sweep 名单，仍须核全其他索引型作业、人工逐例查看等缺口。

最有用的单项备份是原机 `/hy-tmp/validation/dim_sweep_tasks.json`；其次是 `/hy-tmp/validation/dim_sweep/{Light,Background,Noise}_libero_{spatial,object}.txt` 或与原作业绑定的对应 JSONL。若无法取得，不再靠复刷官方旧池来声称独立；按既有决定另行预注册前瞻集，预先固定生成器、强度、种子、源参考、统计与排除规则后再计分，明确区别于官方留出。维持已封存的无 EMA 方法及既有门禁。此轮没有做策略推理，没有触碰受保护样本或计算新的成功率。
