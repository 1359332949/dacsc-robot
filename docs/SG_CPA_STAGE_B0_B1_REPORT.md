## 1. B0：数据可用性清单

### 1.1 四类信号需要的字段

| 信号 | 需要的最小原始字段 | 现有归档是否具备 | 能否从历史数据恢复 |
|---|---|---|---|
| 多视图一致性 | 每个 replan 的 `o_t`（双相机原图）+ 多视图动作块 | ❌ 只有 `view_distances`（4 个数，SG-CPA 旧诊断），无图/无动作块 | **不能** |
| 历史动作连续性 | 上一动作块未执行尾部 + 当前 replan 的动作块/执行动作 | ❌ 执行动作与动作块未落盘 | **不能** |
| 未来视觉预测 | `o_t`、实际执行动作、`o_{t+1}` | ❌ 无图序列 | **不能** |
| 已验证成功动作 | 成功 episode 的动作块/状态轨迹 + 成功标签 | ⚠️ 只有 episode 级 success，无动作/状态轨迹 | 只能做 episode 级 Oracle 上界，**不能做逐动作比较** |
| （现有）loss 信号 | 每个 replan 的 loss、β、梯度等 | ✅ `diag_sg_cpa/*/*.json` 有 | 可以算 loss 轨迹，但**没有任务进度 p**，只能预测最终 success |
| 基线变量 | task_id、episode 时间、当前进度 p | ⚠️ task_id/时间可得；**进度 p 未记录** | 进度不可恢复 |

### 1.2 现有归档字段实况（`p43/diag_*`）

episode 级：`task_id, init_state_index, seed, replans, updates, gate_mode, mode, threshold, result(success/steps/updates)`；
replan 级：`index, score, active, updates, probe_before, probe_after`；
update 级（SG-CPA）：`loss, g_norm, Δβ, local/cumulative A change, backtracks, retained, medoid_index, view_distances, beta snapshot, action_seed/view_seed`。

**没有**：原始图像、状态向量、动作块、执行动作、`o_{t+1}`、任务进度。

### 1.3 B0 结论（硬门槛）

> **现有归档不足以对四类信号做公平比较。**
> 不能用 `view_distances` 代理"多视图一致性"、不能用最终 success 代理"任务进展"、
> 不能用 loss 轨迹代理"未来视觉预测"。必须补齐数据采集条件后才能进入 B1。

**最小数据采集规格（需单独授权环境步进）**：
每个 replan 保存：
- `o_t`（agentview + eye_in_hand，uint8/JPEG）、state、instruction；
- 更新前 β、候选更新 Δβ、更新后 β；
- 更新前后的动作块（固定 latent 采样向量）、实际执行动作、`o_{t+1}`；
- task_id / episode / seed / replan index / 时间戳；episode 结束 success；
- **任务进度 p**：按任务预定义（见 B1）；
- 建议规模：2 域 × 3 任务 × 5 episodes × ~10 replans ≈ 300 个 replan 样本（图像存 JPEG，约 100–300 MB）。

## 2. B1：实验设计（预注册，不执行）

### 2.1 样本与目标

- 样本单位：replan `t`；
- 目标：`Δp_{t,H} = p(s_{t+H}) − p(s_t)`；**预注册修订：H=12 环境步**（=2 个 replan × exec_len 6），
  因为 block_pos 只在 replan 时记录；不再使用 H=10；
- `p` 必须**先于实验定义**，且任务内可比（建议：操作类任务用"物体到目标位姿的距离/子目标完成标志"的归一化进度；
  不使用最终 success 作为唯一 p；不同套件允许不同 p 定义，但必须写入配置）。

### 2.2 四类信号（统一方向：分数越高越"应允许更新"）

| 信号 | 计算（更新前 / 延迟） | 注意 |
|---|---|---|
| 多视图一致性 | `−mean_{i<j} d(A_i,A_j)`（K 视图动作） | 一致 ≠ 正确 |
| 历史动作连续性 | 当前计划尾部与上一 leftover 的一致性（SALT 定义） | 连贯 ≠ 成功 |
| 未来视觉预测 | `−‖r̂_{t+1} − r_{t+1}‖`，**只能在 t+1 观测后计算** | 标记为延迟/事后验证，不能当更新前信号 |
| 已验证成功动作 | 与成功轨迹动作块的相似度 | **Oracle 上界**；LOO 下若训练折无该 task 的成功参考则标"不可估计"，不进入普通排名 |

### 2.3 评价（预注册）

1. **任务留出**：leave-one-task-out；每折在留出任务上评估信号 → Δp 的 Spearman/秩相关；
2. **基线增量**：LOO 主 baseline **不含 task_id one-hot**（留出任务无法估计其系数），
   使用 suite/domain、episode time、当前 p_t、最近动作幅度；task_id baseline 仅用于同任务分析；
3. **不确定性**：任务簇 bootstrap（1000 次）90% CI；任务内置换检验（打乱 Δp 标签，p<0.05）；
4. **分域报告**：Camera / Background / Noise / Light 分别报告，不合并成单一数字；
5. **提前停止**：若某信号在 ≤1 个域对基线的增量 CI 含 0，则标记"未通过 B1"，不进入 B2/B3；
6. **样本量**：当前设计约 300 replan 样本、6 任务簇；功效有限，结论只能作为"是否值得继续"的筛选。

### 2.4 B1 验收门槛

| 检查 | 通过条件 |
|---|---|
| 数据完整性 | 四信号的原始字段齐全、时间对齐正确（含延迟信号标记） |
| 增量预测力 | 至少 2 个域上，相对基线的增量 CI 不含 0 且方向一致 |
| 稳定性 | 留一任务评估中，信号方向在 ≥5/6 任务一致 |
| 无泄漏 | 未来视觉信号只用于"事后验证"，不进入"更新前可用"表 |

不通过 → 停止该信号，不补造代理。

## 3. B2：更新效用识别（仅可行性设计，未授权执行）

- 定义 `τ_t = Δp_{t,H}(θ+Δθ) − Δp_{t,H}(θ)`；
- 需要**同一初始状态**下的成对模拟分支（更新 vs 不更新），匹配环境 RNG、动作 latent、执行步数；
- 这是**模拟器反事实评估**，不是物理 rollout，但需要环境步进与两倍计算；
- 只有得到 τ 的正负标签后，才能评估"信号能否预测一次更新是否有益"；
- **未获得该授权前，B2 结论必须标注为"未验证"**，不能用 B1 的 episode-level 结果替代。

## 4. B3：离线决策验证（设计草图，未执行）

- 固定候选更新集，定义接受/拒绝策略：`accept if signal > τ_s`；
- 报告误接受代价（接受了负 τ 的更新）与误拒绝代价（拒绝了正 τ 的更新）；
- 与 always-accept / always-reject / Oracle 比较；
- 只有 B1+B2 通过后才进入，且仍不自动 rollout。
