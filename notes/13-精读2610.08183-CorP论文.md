# 精读 `2610.08183` CoRP：Compact Robot Policies Need Fine-Grained Visual Representations

> 2026-10-16 全文精读（arXiv HTML v1）。ICLR 2027 投稿。
> **这篇论文对我们的价值：既是强 motivation，又是一套可直接借鉴的消融模板，还纠正了我们一个错误判断。**

---

## 一、它做了什么

**CoRP = 48.9M 参数的操作策略，不用 VLM、不用视频生成先验。**

架构分两段：

```
多视角图像 ─►[视觉编码器]─► 256 个 patch token
                              │
                              ▼
                    [learned-query resampler]  ← 用语言 FiLM 调制 query
                              │  压成 K=48 个 token
                              ▼
              [DiT-style Transformer]  ← flow matching 动作生成器
                              │
                              ▼
                        动作序列
```

**关键配置（实测自论文）**：

| 组件 | 用的什么 | 是否微调 |
|---|---|---|
| **视觉编码器** | **DINOv2 预训练的 ViT-S/14**（22.1M），多视角共享权重 | **✅ 联合微调**（不是冻结！） |
| 语言编码器 | **T5-Efficient-Tiny** | ✅ 联合微调 |
| 融合 | learned-query cross-attention resampler（P=256 → K=48） | ✅ |
| 动作头 | DiT-style Transformer + **flow matching**（τ~Beta(1.0,1.5)，N=10 Euler 步） | ✅ |
| 辅助损失 | task-classification loss（λ=0.01） | — |

## 三、它的四个消融（**这是最值得借鉴的部分**）

### 4.3 预训练视觉编码器有用吗？→ **YES**

**2×2 交叉设计**：{随机, 预训练} × {ViT-S/14 (22.1M), ResNet-34 (21.5M)}，**参数匹配**

| 变体 | Spatial | Object | Goal | Long | **Avg** | NMAE | R² |
|---|---|---|---|---|---|---|---|
| Random ResNet-34 | 91.2 | 97.8 | 72.8 | 66.6 | 82.1 | 0.12 | 0.54 |
| **Pretrained ResNet-34 (ImageNet)** | 85.4 | 98.8 | **37.0** | 76.8 | **74.5** | 0.09 | 0.73 |
| Random ViT-S/14 | 84.4 | 95.6 | 86.0 | 46.4 | 78.1 | 0.11 | 0.59 |
| **Pretrained ViT-S/14 (DINOv2)** | 98.2 | 99.4 | 95.8 | 94.4 | **97.0** | 0.07 | 0.81 |

**三条结论**：
1. 预训练 ViT 比其他变体高 **≥14.9 点**
2. **单靠任一因素都不行**：随机初始化时 ViT 不比 ResNet 好（78.1 vs 82.1）；**ImageNet 预训练反而拉低 ResNet**（74.5 vs 82.1）
3. 四个变体的**任务分类准确率都是 100%**，但预训练 ResNet 在 Goal 上只有 37.0%
   → **"它们知道该做哪个任务，但缺乏细粒度视觉信息去执行"**

### 4.4 只预训练不做适配够吗？→ **NO（★ 这条纠正了我们的判断）**

| 变体 | Avg | NMAE | R² |
|---|---|---|---|
| **冻结** DINOv2 | **77.2** | 0.16 | **0.24** |
| **微调**（默认） | **97.0** | 0.07 | **0.81** |

**论文原话**：
> "The frozen policy (77.2%) performs no better than a randomly initialized ViT trained end-to-end (78.1%)... freezing reduces R² from 0.81 to 0.24 and doubles NMAE... **frozen features retain much less action-relevant detail**"

### 4.5 需要语言条件吗？→ **看情况**

- LIBERO-**Goal**：95.8% → **9.2%**（灾难）
- 其他 suite：最多掉 11.2 点
- **RoboTwin 2.0：去掉语言反而更好**（Clean 78.50 vs 75.78；Rand 76.06 vs 73.36）
- 判据：**只有"观察无法唯一确定目标"时才需要语言**
  - LIBERO-Goal：同一场景对应多个目标 → `p(κ|o,s)` 接近均匀 → 需要语言
  - RoboTwin：每个场景就确定了任务 → 语言没用甚至有害

### 4.6 信息瓶颈有用吗？→ **看是哪种**

| 变体 | Avg |
|---|---|
| All Tokens（P=256 全用） | 83.2 |
| All Tokens + VIB | 77.8 ⬇️ |
| **Partial Tokens（K=48 resampler）** | **97.0** ⬆️ |
| Partial Tokens + VIB | 75.9 ⬇️ |

**结论**：
- **硬性、指令感知的 token 预算赢（+13.8）**
- **VIB（变分信息瓶颈）反而更差**，因为它的 KL 惩罚是**任务无关的**——把所有 token 压向同一先验
- 他们的 resampler 是**指令感知的**：通过 FiLM 调制的 query 按指令分配容量

**🔑 这条对我们的方法论是强背书**：
> "盲目压缩/无差别正则化"不行，"**按语义信号（指令/域）有选择地压缩**"才行。
> 我们的门控正是"按域标签有选择地抑制通道"，而不是"无差别 Dropout"。

## 四、对我们的三点直接影响

### ① 强 motivation（直接可引）

DP 在两个 benchmark 上都垫底，**在 Randomized 下崩到 0.6%**，论文自己下的结论是
**"an early sign that the visual representation drives robustness"**。

→ 我们的选题正当性不再需要自己论证，**第三方独立测量给出了证据**。

### ② ⚠️ **纠正我上一轮的错误判断**

我上一轮说："SmolVLA 冻结视觉塔反而是我们的机会——证明'不重训视觉塔也能提升'是强论点。"

**这篇论文的 4.4 直接反驳了这个判断的基础**：
- 冻结 DINOv2 特征 → 成功率掉 **19.8 点**（97.0 → 77.2）
- 冻结特征的 **R² 只有 0.24**（vs 微调 0.81）→ **动作相关信息本来就少**
- 冻结的表现**不比随机初始化端到端训练好**（77.2 vs 78.1）

**含义**：如果冻结特征本身就缺乏动作相关信息，那"在冻结特征上做通道门控"的**上限就很低**。

**修正后的 L2 设计**：
```
❌ 旧方案：SmolVLA 冻结视觉塔 + 只训门控
✅ 新方案：SmolVLA 微调视觉塔 + 门控  vs  微调视觉塔（不加门控）
          或者：只微调视觉塔的后几层 + 门控
```
**必须做"微调 vs 微调+门控"的公平对比**，而不是"冻结 vs 冻结+门控"。

### ③ 它的局限第一条 = **我们的空间**

论文原文：
> "**Closed-set evaluation.** Our benchmarks measure **in-distribution control on closed task sets; we do not evaluate the open-world semantic and physical generalization** that VLAs and WAMs target. Whether pretrained, task-adapted, and compressed representations remain sufficient in that regime... **is an open question.**"

**它明确说"我不研究开放世界泛化"，并把它列为 open question。而外观域泛化正是开放世界泛化的一部分。**

其他两条局限也值得注意：
- **缺少"监督预训练 ViT"对照** → 无法分离 DINOv2 的 patch 级预训练贡献（他们自己说这是下一步）
- 真机实验只有 3 个任务、无真机基线

## 五、值得借鉴 vs 不值得照搬

### ✅ 值得借鉴

| 做法 | 为什么 |
|---|---|
| **2×2 交叉消融**（分离"架构"和"预训练"） | 我们的门控消融也该这样设计：分离"门控"和"域标签"的贡献 |
| **NMAE / R² 特征探针** | 不只报成功率，还报"特征里还剩多少动作信息" → **这才是机制证据**。我们的方法必须做这个 |
| **"只改一个因子，其他全部固定"的纪律** | 他们说 "every variant uses the default configuration... changing only the factor under study" |
| **把 DP/ACT 归为"无预训练先验"对照组** | 我们的对比表可以直接沿用这个分组 |
| **指令感知 vs 任务无关的对比设计**（4.6） | 我们做"域感知门控 vs 无差别 Dropout"的对比，逻辑完全同构 |
| **闭集/开集"局限"的写法** | 论文里明确承认不覆盖开放世界泛化 → 我们可以引用它来说明我们的贡献边界 |

### ❌ 不值得照搬

| 做法 | 为什么 |
|---|---|
| resampler / token 压缩 | 他们是 **token 级** 压缩，我们是**通道级**抑制——层级不同 |
| task-classification 辅助损失 | 他们的目的是让表示保留任务信息；我们的目标是**去掉域信息**，目标相反 |
| flow matching 动作头 | 可作**可选**消融（L3），但不是我们方法的必需 |
| T5 语言编码器 | 我们的 DP fork 已有 768 维语言嵌入，不必换 |

## 六、更新后的实验设计

```
L0   CPU 机制验证（零成本）

L1   主实验：DP + ResNet18（全部消融，单卡 24–48 GB）
     ├─ 基线：DP 原样
     ├─ 我们的：DP + 通道门控
     └─ ★ 新增：DP + R3M 预训练 ResNet18（回应 4.3）
        —— 4.3 说"预训练 + 架构"要配合才有效；我们的 fork 原生支持 weights="r3m"

L1b  ★ 新增：特征探针（NMAE / R²）
     —— 学 4.4 的探针设计：证明门控后"动作相关信息没有被破坏"

L2   迁移验证：SmolVLA
     ★ 修正：微调视觉塔 + 门控  vs  微调视觉塔（公平对比），不做纯冻结

L3   （可选）DP + flow matching 动作头
```

### 新增的必做对比（来自 4.6 的设计逻辑）

| 对比 | 目的 |
|---|---|
| 域感知门控 **vs** 无差别 Dropout | 证明"选择性抑制"优于"随机抑制"（同构于 4.6 的 resampler vs VIB） |
| 门控 **vs** 全部微调视觉塔 | 证明我们的方法参数效率更高 |
