# 55 - 策略数据划分与 held-out 指标修复

日期：2026-10-22
服务器：`i-2.gpushare.com:40424`
数据：RoboCasa365 atomic，61/61 tasks

## 1. 固定协议

```text
train styles:    11-30
val styles:      31-40
test styles:     41-50
reserved styles: 51-60
```

划分单位是原生 style + episode：

- 区间互斥，训练/验证/测试 episode 不重叠；
- val/test 在各自 10 个 style 内均衡抽样；
- test 只在训练正常结束后评估一次；
- test 不参与 checkpoint monitor、early stopping 或超参数选择。

## 2. 代码修复

### 2.1 训练 sampler

`DomainBalancedSampler` 增加 `allowed_styles`：

- policy 训练 sampler 只允许 styles 11-30；
- 无 style 标签的样本不会进入 allowlist 训练池；
- cache signature 包含 allowlist；
- batch 补齐池只由 allowlist 内索引组成。

### 2.2 val/test 索引

`DomainLerobotCotrainingDataset` 使用：

```yaml
train_style_min: 11
train_style_max: 30
val_style_min: 31
val_style_max: 40
test_style_min: 41
test_style_max: 50
reserved_style_min: 51
reserved_style_max: 60
```

启动时构造三组索引并断言不相交。val/test 的 cap 改为跨所有 style 的均衡抽样，避免短评估只覆盖前几个 style。

### 2.3 统计不碰 test

normalizer 默认只从 train styles 抽样 512 个 step 拟合 state min/max：

```yaml
train_only_normalizer: true
normalizer_max_steps: 512
```

action、language、image 仍使用 identity/range normalizer。

### 2.4 指标语义

```text
train_action_mse_error  仅训练 batch 诊断
val_action_mse          styles 31-40 上的 predict_action MSE
test_action_mse         styles 41-50，训练结束后仅一次
```

- checkpoint monitor 是 `val_action_mse`，不是 test；
- 没有 val 指标时拒绝运行 test；
- test 使用 val 选出的模型权重，不参与模型选择；
- 汇总脚本优先读取 `val_action_mse` 与 `test_action_mse`。

## 5. 当前边界

该修复只保证：

```text
数据划分正确
训练统计不碰 val/test
val/test 指标来自各自 loader
test 只在最后运行
```

它不证明任何门控方法有效，也不替代动作 MSE、闭环 success rate 和 3-seed 统计。

后续任何 DomainDrop 实验必须基于原生 source `style_id`；测试风格不能参与域头监督或模型选择。
