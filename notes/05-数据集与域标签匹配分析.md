# 数据集 × 我们方法的需求匹配分析（重点：域标签）

> 2026-10-16。判定依据全部来自源码实测，不是推测。

## 一、我们的方法对数据提了 10 条硬要求

从方法文档（§3 数据划分、§6 公式、§10 评测）反推：

| # | 要求 | 服务于哪个机制 |
|---|---|---|
| R1 | 多相机 RGB 观测 | 通道级视觉分析、门控 |
| **R2** | **每个 episode 有外观域标签** | **域敏感性 u^grad / u^disc、门控目标、域分类器** |
| **R3** | **每个 episode 有布局标签** | 把几何变量从外观变量里分离出来 |
| R4 | 任务标签 | 多任务训练、按任务聚合统计 |
| R5 | 机器人状态 + 连续动作 | Diffusion Policy 训练 |
| **R6** | **同一任务下有多个域（域与任务不绑定）** | 否则域分类器学到的是任务不是域 |
| **R7** | **每个域有足够样本** | 域分类器准确率要高于随机水平 |
| **R8** | **留出的未见域 + 闭环成功率评测** | 泛化度量 Δ_gen、风格稳定性 Var_d(S_d) |
| **R9** | **同场景可换外观重渲染（反事实对）** | §6.10 动作一致性 L_cons |
| R10 | 环境可控（能指定 layout/style 重置） | 消融、扩展测试、域扫描 |

**加粗的 6 条全部围绕域标签。** 没有域标签，DACSC 的核心机制（通道域敏感性）根本算不出来。

## 三、源码级证据（为什么只有 RoboCasa365 行）

### RoboCasa365 ✅ —— 域标签是一等公民

`robocasa/environments/kitchen/kitchen.py` 的 `get_ep_meta()` 每个 episode 都写：

```python
ep_meta["layout_id"]      = int(self.layout_id)       # 几何域轴
ep_meta["style_id"]       = int(self.style_id)        # ★外观域轴
ep_meta["object_cfgs"]    = [...]                     # 物体摆放
ep_meta["fixtures"]       = {...}
ep_meta["gen_textures"]   = self._curr_gen_fixtures    # ★纹理级细节
ep_meta["lang"]           = ""
```

落盘位置：`lerobot/extras/episode_XXXXXX/ep_meta.json`（每 episode 一个文件）。

**同一段代码还证明 R9 可行**：重置时

```python
if "layout_id" in self._ep_meta and "style_id" in self._ep_meta:
    self.layout_id = self._ep_meta["layout_id"]
    self.style_id  = self._ep_meta["style_id"]
```

→ 读入某 episode 的 `ep_meta.json`，**只改 `style_id`、保持 `layout_id` 与 `object_cfgs` 不变**，重置环境，就得到「同布局、同物体摆放、不同外观」的反事实对 —— 这正是 L_cons 需要的 o_t / o_t⁺。**其他数据集都做不到。**

再加上伪 id 语义（源码 `scene_registry.py`）：

```
LAYOUT_GROUPS_TO_IDS = {-1: 1..10 (test), -2: 11..60 (train), -3: 1..60}
STYLE_GROUPS_TO_IDS  = {-1: 1..10 (test), -2: 11..60 (train), -3: 1..60}
```

→ 训练域（11–60）与测试域（1–10）**在源码层面就是分离的**，且 `env_kwargs` 支持 `style_ids` / `layout_and_style_ids` 精确指定。

### RoboTwin 2.0 ❌ —— 随机化了外观，但没记下来

它**确实**随机化外观（`envs/_base_task.py`）：

```python
if self.random_background:
    texture_type = "seen" if not self.eval_mode else "unseen"     # ← 甚至做了 seen/unseen 划分
    wall_texture, table_texture = np.random.randint(0, file_count), np.random.randint(0, file_count)
    self.wall_texture, self.table_texture = f"{texture_type}/{wall_texture}", f"{texture_type}/{table_texture}"
```

配置 `env_cfg/task_config/demo_randomized.yml` 里有 `random_background` / `random_light` / `cluttered_table` / `random_table_height`。

**但保存时只写了关节轨迹**：

```python
def save_traj_data(self, idx):
    traj_data = {"left_joint_path": ..., "right_joint_path": ...}
```

→ 用的是 `np.random.randint`，且 `use_seed: false`，**选了哪张墙纸/桌面纹理无法从数据里还原**。要用它就得自己插桩重采数据。

### robomimic + RoboSaGA ❌ —— 域是"合成"的，不是"标注"的

- robomimic 数据集本身只有一个固定场景（`env_args` 里是环境名与配置），**没有场景/外观域标注**
- RoboSaGA 的做法是外挂一个 OOD 背景池（`backgrounds.zip`）做显著性引导叠加，评测时用 `eval_visual_domain_shifts.py` 比 in-domain / off-domain 成功率（脚本里有 `offdomain_type`）
- 即：**域定义来自增广方法本身，而不是数据里的标签**

这恰恰暴露了我们和 RoboSaGA 的根本区别：

> RoboSaGA 走"无标签 + 增广合成域"，所以只能在数据层面做不变性；
> DACSC 要算**通道级域敏感性**（u^disc 需要按域统计激活分布、u^grad 需要域分类器），**必须有真实域标签**。
> 没有标签，我们的核心机制无法成立 —— 而这正是我们方法相对它的贡献所在。

## 四、结论

### Q: 哪个数据集符合我们的方法？

**只有 RoboCasa365 原生满足。** 它是这批候选里**唯一**同时提供：

1. 每 episode 的 `style_id`（外观域标签）+ `layout_id`（几何标签）
2. 域与任务不绑定的采样机制
3. 源码层面分离的 train/test 域集合
4. 可指定 style 重置环境 → **能造反事实对**
5. 官方闭环评测协议（50 rollouts/task）

### Q: 我们的域标签需求被满足了吗？

**被满足了，而且这是 RoboCasa365 相对其他基准的独特价值。** 可以写进论文作为选型理由（不是"因为它新"，而是"因为只有它能支撑通道级域分析"）。

### 但有 4 件事必须先验证（阶段 0 审计的活）

| # | 待验证 | 为什么重要 | 怎么验 |
|---|---|---|---|
| 1 | 每 task 内覆盖多少 style？每 style 多少 episode？ | R7：样本不足则域分类器 ≈ 随机 | `scripts/audit_dataset.py` |
| 2 | style 与 task 是否耦合？ | R6：耦合则域分类器学到任务 | 同上（Cramér's V） |
| 3 | style 是否有足够样本做域分类器 | 60 类若过于稀疏 → 需归并粗粒度外观域 | 同上 |
| 4 | target split 同时改了 layout+style+objects | R8：**无法单独归因"外观"** | 必须用 pretrain 内部 style 划分做主实验，target 只作二次验证 |

第 4 条尤其关键：官方 `target` split 把 **layout、style、物体**一起换掉了，所以**不能**用它来证明"我们的方法提升了外观泛化"——那是三个变量的混合效应。**主实验必须是我们设计的 pretrain 内部 style holdout（11–40 / 41–50 / 51–60）**，target 只能作为"在官方协议上也有效"的补充证据。这一条已经写进方法文档 §3.3 和 §10.3。

## 五、决定（2026-10-16）

**采用 RoboCasa365 作为唯一数据源。** 理由：

1. 唯一提供 per-episode `style_id`（外观域标签）与 `layout_id`（几何标签）的候选；
2. 唯一能在源码层面分离训练域（11–60）与测试域（1–10）；
3. 唯一支持"同布局同物体、换 style 重渲染"→ 能造 L_cons 需要的反事实对；
4. 官方闭环评测协议（50 rollouts/task）现成；
5. 许可清晰：代码 MIT + 资产/数据 CC BY 4.0。
