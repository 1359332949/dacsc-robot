# 架构严格对齐修复（2026-10-20）

针对严格校验，选择方案 B：恢复 CoRP 风格的 K-token 条件，而不是接受 flatten 后的单向量。

## 1. Resampler

- 输出从 `[N, K*D]` 改为 `[N, K, D]`
- K=48，默认每 token 64 维
- 每个视角单独 cross-attend
- 多视角共享同一套 query / resampler 权重

## 2. DiT condition

每个观测步现在送入：

```text
1 个 low-dim/language token
+ V × K 个 visual token
```

所以：

```text
n_obs_steps=2
V=3
K=48
→ cond tokens per obs step = 145
→ DiT cond token count = 290
```

`TransformerForDiffusion` 的 `n_obs_steps` 使用 token 数（290），而不是原始观测步数（2）。

## 3. 语言 FiLM

`LearnedQueryResampler.forward(tokens, lang_emb)`：

```text
lang_emb → LayerNorm → Linear → (gamma, beta)
query = query * (1 + gamma) + beta
→ cross-attention to patch tokens
```

语言不再只通过 low_dim/fuse 注入，而是直接调制 learned query。

## 4. 更正 DFR-like 命名

原 `dfr_head` 实际是：

```text
frozen observation encoder + train DiT head
```

已更名为：

```text
frozen_encoder_head
```

它不是严格 DFR 的最后一层重训；笔记 39 已同步修改。

## 5. 配置安全默认

`train_dinov2_bs192.yaml` 和 `train_dinov2_flow.yaml`：

```yaml
dataloader.batch_size: 30
val_dataloader.batch_size: 8
training.num_epochs: 1
training.max_train_steps: 51
training.max_val_steps: 32
```

并注明：

- `max_train_steps` 是每 epoch 步数；
- `val_every` 是 epoch 级；
- flow 配置的 `noise_scheduler` 仅保留给官方基类构造，flow 路径不使用。
