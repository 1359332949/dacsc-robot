# 算力门槛调研：我们到底能做哪一种？

> 2026-10-16。数字全部来自官方源码/文档/论文摘要，不是估计。

## 一、硬门槛：决定性的那张表

| 方案 | 规模 | 视觉编码器 | 官方训练硬件要求 | 来源 | 我们能做吗 |
|---|---|---|---|---|---|
| **DP（RoboCasa fork）** | **106 M** | **ResNet18（从零训）** | **≥24 GB（48 GB+ 佳）** | RoboCasa 官方文档 | ✅ **单卡** |
| ACT | ~80 M 级 | ResNet18 | 低（batch_size 16） | XPolicyLab 脚本 | ✅ 单卡 |
| **SmolVLA** | **500 M VLM + expert** | **SigLIP（默认冻结）** | **「单 GPU 训练，消费级 GPU 甚至 CPU 部署」** | arXiv 2506.01844 摘要 | ✅ **单卡** |
| RDT-1B | 1.2 B | SigLIP + DINOv2 + DiT | ≥48–80 GB | arXiv 2410.07864 | ⚠️ 勉强 |
| **π0 / π0.5** | **2.3 B**（gemma_2b + 300m expert） | PaliGemma / SigLIP | **≥80 GB（H100/H200）** | openpi README + `pi0_config.py` | ❌ |
| **GR00T N1.5** | ~2 B+ | Eagle-2 | **≥100 GB（B100/H200）** | RoboCasa 官方文档 | ❌ |
| **WAM（Awomo 等）** | 5 B+ | Qwen3-VL + Wan2.2 视频扩散 | ≥100 GB | 推断（比 π0 更大） | ❌ |

**分界线非常清楚：24–48 GB 与 80–100 GB 之间隔了 4 倍，而且是 H100/H200 级别。**

## 二、结论：我们只有两个现实选项

1. **DP（ResNet18）** —— 唯一"从零训 + CNN 可解释 + 能跑几十组消融"的骨架
2. **SmolVLA** —— 唯一"现代 VLA + 单卡可训练"的骨架

π0 / π0.5 / GR00T / WAM **在单卡上连一组都跑不了**，不是"要不要选"的问题，是"物理上做不到"。

## 三、正面回应："DP 老了、ResNet18 不值得研究"

你的直觉**对了一半**。必须把两件事分开：

| | 作为**性能载体** | 作为**机制研究的显微镜** |
|---|---|---|
| ResNet18 | ❌ **确实过时**（排行榜垫底，差 5–6 倍） | ✅ **仍是标准工具** |
| 证据 | DP 15.7 / Awomo 86.5 | 图像域泛化的经典方法（DomainDrop、PLACE、RSC、RoboSaGA）**全部**在 ResNet18/50 上验证；我们引用的方法参考代码也全是 ResNet 系 |

**关键区分：我们的贡献不是"一个更强的模型"，而是"一套识别通道级域敏感性的方法"。**
研究方法需要的是能**看得清、改得起、跑得多**的骨架——这在 ResNet18 上满足，在 2B 冻结 ViT 上不满足。

**但你的担心有一半是对的**：如果论文只报 ResNet18，会被批"没跟上"。所以要 L2 迁移。

## 四、SmolVLA 的关键发现（双刃）

```
vlm_model_name        = "SmolVLM2-500M-Video-Instruct"    # SigLIP 视觉塔 + SmolLM2
freeze_vision_encoder = True      ★ 视觉塔默认冻结
train_expert_only     = True      ★ 只训 action expert
num_steps             = 10        # flow matching（不是 DDPM）
chunk_size            = 50
```

- **挑战**：默认配置下**视觉塔是冻结的**，而我们的方法恰恰要动视觉编码器的通道。
- **机会（更重要）**：如果我们的门控能在**冻结的视觉塔**上生效（只训门控参数），那就是一个**比原方法更强的论点**：
  > "不重训视觉塔，仅靠轻量通道门控就能提升外观泛化"
  这正是工业部署需要的（没人愿意重训 2B 视觉塔）。
- **门控参数量极小**：ResNet18 上 3 相机 × 1920 通道 = **5760 个标量**；SigLIP 视觉塔（12 层 × 768）约 **9 千个标量**。相对 500M/106M 都是 0.001% 量级。

## 五、推荐方案：三层实验设计

```
L0  机制验证（本机 CPU 就能做）
    ├─ 恒等门控不改变基线输出
    ├─ 门控形状/梯度/EMA 单元测试
    └─ 零成本、零数据

L1  主实验：DP + ResNet18（全部消融在这）
    ├─ 为什么：唯一能跑完 28 组消融的骨架，且通道可解释
    ├─ 硬件：单卡 24–48 GB
    └─ 产出：Δ_gen（已见 vs 未见 style 成功率）、门控可视化、通道分析

L2  迁移验证：SmolVLA + 冻结 SigLIP 视觉塔（只需 1–2 组配置）
    ├─ 为什么：唯一负担得起的现代 VLA；且"冻结视觉塔上生效"是强论点
    ├─ 硬件：单卡
    └─ 产出："机制 backbone-agnostic" 的证据 + 堵住"骨架过时"的批评

（可选 L3）flow matching head 版本：把 DP 的 DDPM 头换成 flow matching
    └─ 成本中等（编码器不变），跟上 DP 家族内部演进
```

**这套设计的关键论点（论文里可以这么写）**：
> 我们在一个可控的、从零训练的小骨架上完整验证机制（L1），
> 并在一个现代 VLA 的**冻结视觉塔**上验证可迁移性（L2）。
> 因此本方法不依赖特定骨干，且不要求重训视觉编码器。

## 六、成本现实提醒（必须提前规划）

DP 官方配置：`num_epochs=1000 × max_train_steps=500 = 50 万步`，`batch_size=192`。
**这是单次训练几十小时量级**。28 组消融 × 3 种子 = 84 次训练，单卡是跑不完的。

必须裁剪：

| 手段 | 官方支持 | 效果 |
|---|---|---|
| `demo_fraction` | ✅ dataset registry 内置（10% / 30% / 100%） | 数据量减到 1/10 |
| 缩短训练步数 | ✅ `max_train_steps` 可改 | 线性减少 |
| 只跑 1 个 task_set | ✅ `atomic_seen`（18 个短任务） | 评测时间大幅下降 |
| 种子数 3 → 2（先 1 个做筛选） | — | 线性减少 |
| 早停 + 验证集筛选 | ✅ `val_every` 已配置 | — |

**评测侧也是瓶颈**：50 rollouts/task × 18 任务 × 最长 7200 步 × 3 相机渲染，是按天计的（官方建议评测机 16 核 / 64 GB）。
