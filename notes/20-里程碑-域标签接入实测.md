## 一、为什么必须自己做

我们的方法完全依赖外观域标签，但官方 `LerobotDataset` 只提供
图像 / 状态 / 动作 / 语言嵌入，**不含 style_id**。

标签藏在 RoboCasa365 的 `extras/episode_XXXXXX/ep_meta.json` 里（见 `kitchen.py` 的 `get_ep_meta()`）：
```json
{"lang": "...", "layout_id": 23, "style_id": 41, "gen_textures": {...}}
```

---

## 二、怎么接（照官方已有模式）

官方 `LerobotDataset.__getitem__` 里已经有这个模式：

```python
trajectory_id, _ = self.all_steps[idx]                # ← 拿到 episode 序号
lang_emb = self._demo_id_to_demo_lang_emb[trajectory_id]
```

**域标签完全照抄这个模式**：
```python
trajectory_id, _ = self.all_steps[idx]
data["domain_id"] = self._demo_to_domain[trajectory_id]   # ← 我们加的
```

映射表在 `__init__` 时扫描 `extras/` 建立。

## 五、★ 两个关键的工程决策

### ① 加了"标签对齐校验"这个安全网

**这是最容易错、且错得最隐蔽的地方**：如果 `extras/episode_XXXXXX` 的序号
与 LeRobot 的 `episode_index` 错位，**域标签会整体张冠李戴，而所有下游代码都不报错**——
模型照常训练，指标照常输出，但结论完全错误。

校验做法：LeRobot 的 `meta/episodes.jsonl` 里每个 episode 有 `length`（帧数），
同序号 `extras/.../states.npz` 的 `states` 行数应当相等。

测试结果：**人为制造错位 → 5/5 全部被检出**。

### ② 发现并修掉一个真设计缺陷

**问题**：`__getattr__` 懒加载如果每次访问都新建类，会导致
两次引用不是同一个类 → `isinstance` 失效 → hydra 实例化得到与检查时不同的类。

**修法**：加模块级缓存。测试⑦就是专门抓这个的（第一版确实返回 False）。
