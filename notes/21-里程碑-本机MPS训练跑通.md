## 二、这次烟测抓出的 3 个真 bug（这是烟测最大的价值）

### Bug 1：门控参数根本不在优化器里 ⚠️

官方 `get_optimizer` 只返回 DiT（两组）+ obs_encoder 的参数，**不含门控**。
结果：梯度算了、但永远不更新 —— **静默失效**，不报错、不掉点，只是方法完全没起作用。

**修法**：在策略里覆盖 `get_optimizer`，追加第 4 组门控参数。

**验证**：`优化器里包含的门控参数数: 12/12` ✓

### Bug 2：门控初始值落在 sigmoid 饱和区，学习慢 1000 倍 ⚠️

`g = σ(η)`，初始 `g=0.999` → `η≈6.9` → `σ'(η) ≈ 1e-3`。
所以 **g 空间的每步变化只有 `lr × 1e-3`**：用主 lr(1e-4) 时 **Δg/步 ≈ 1e-7**，
训练一百万步也几乎不动。

**修法**：门控学习率必须显著高于主 lr → 配置默认 `gate_learning_rate: 1e-2`（100×）。

**验证**：改用 `gate_init=0.9 + lr=0.5` 后，8 步内 4607/4608 个门控都动了。

### Bug 3：MPS 不支持 float64 ⚠️

域统计用 float64 累积（为数值稳定），但 **Apple MPS 框架不支持 float64**：
```
TypeError: Cannot convert a MPS Tensor to float64 dtype
```
**修法**：在设备上算完归约 → **先 `.cpu()` 再转 float64**，在 CPU 上累积
（体量 12×50×384 ≈ 23 万，仅 3.7MB，无性能影响）。

## 三、交付物

```
dacsc/stub_dataset.py       合成数据集（外观依赖域标签、动作不依赖域）
scripts/train_smoke_test.py 训练烟测（走官方 workspace.run()）
```

**复现**：
```bash
SMOKE_STEPS=8 SMOKE_BS=8 ./.venv/bin/python scripts/train_smoke_test.py
```

**合成数据集的设计要点**（否则烟测没意义）：
- 每个域注入**专属颜色偏移 + 专属条纹纹理** → u^disc 有东西可找
- **动作只依赖物体位置，与域无关** → 正好验证我们的核心假设：
  "域信息可以去掉，任务信息必须保住"

## 四、性能边界（重要）

| 指标 | 值 |
|---|---|
| 本机 batch=8 单步 | ~2.3 s |
| 官方配置 | batch=192，1000 epochs × 500 steps = **50 万步** |

**结论**：本机能跑通**烟测与极小规模实验**，但**跑不了正式训练**——
按 2.3 s/步(batch 8)外推，batch 192 单步约 1 分钟，50 万步 = **约 350 天**。

**所以分工是清楚的**：
- **本机（Mac/MPS）**：写代码、验证形状/梯度/学习通路、跑极小规模 sanity check
- **GPU 机器（租）**：正式训练与消融
