# 里程碑：官方基线在本机 CPU 上跑通（2026-10-16）

## 结论

**不需要数据、不需要 GPU，官方 Diffusion Policy 基线已经可以完整实例化并前向。**
这意味着 DACSC 的门控模块可以在本机写完并做单元测试，不用等数据。

## 实测结果

| 项 | 值 |
|---|---|
| 配置 | `train_diffusion_transformer_bs192` + `task=robocasa/pretrain_human300` |
| 解析值 | `horizon=10` / `n_obs_steps=2` / `n_action_steps=8` / `obs_as_cond=True` |
| **总参数** | **106.03 M** |
| **其中 obs_encoder** | **42.45 M**（占 40%） |
| 实例化耗时 | 8.7 s（CPU） |
| 前向耗时 | 4.79 s（CPU，含 100 步去噪） |
| 输出 | `action [1,8,12]`、`action_pred [1,10,12]` ✓ 与 H=10 / n_action=8 一致 |

## 门控插入点（精确定位，实测）

```
obs_nets.robot0_agentview_right_image.backbone   → ResNet18ConvFiLM（8 blocks + 8 FiLM）
obs_nets.robot0_agentview_left_image.backbone    → ResNet18ConvFiLM（8 blocks + 8 FiLM）
obs_nets.robot0_eye_in_hand_image.backbone       → ResNet18ConvFiLM（8 blocks + 8 FiLM）
```

**注意：是 3 个独立实例（每相机一个），共 24 个 conv block。** 门控必须按相机分别注入，
且要决定域统计是"逐相机独立"还是"跨相机共享域标签聚合"（设计决策，见下）。

逐 block 输出（224×224 输入，hook 实测）：

```
[1,64,56,56] [1,64,56,56] [1,128,28,28] [1,128,28,28]
[1,256,14,14] [1,256,14,14] [1,512,7,7] [1,512,7,7]
```

与静态推导完全一致。

## 两个必须记录的 caveat

1. **兼容 shim**：官方 fork pin 的是 `diffusers==0.11.1`，本机装的是 `0.41.0`。新版把
   `diffusers.optimization` 里的 `Union` / `Optional`（typing 符号）移走了，脚本在**内存里补回**，
   **没有修改官方仓库源码**。报告里有 `compat_shims` 字段记录。
   → 正式训练环境请按官方 `conda_environment.yaml` 装 0.11.1，避免这个 shim。
2. **dummy normalizer**：`predict_action` 需要 normalizer，平时由 `dataset.get_normalizer()` 设置。
   冒烟测试用随机张量 fit 了一个，仅用于验证前向路径，不代表真实数据统计量。

## 由此产生的设计决策（待定）

1. **门控是否跨相机共享**：3 个相机各有独立的 `ResNet18ConvFiLM`。选项：
   - (a) 每相机独立门控（参数 ×3，但域敏感性可能相机相关）
   - (b) 共享门控（参数少，假设域敏感性跨相机一致）
   → 建议先做 (a)，把 (b) 作为消融。
2. **域统计的聚合层级**：`u^disc` 按 (layer, channel, style) 统计激活分布时，
   是按单相机统计，还是把 3 个相机的同层通道拼起来统计？
   → 建议单相机统计（通道语义不同），但在门控正则里跨相机汇总。
3. **门控参数预算**：24 个 block 共 `64+64+128+128+256+256+512+512 = 1920` 通道 ×3 相机 = **5760 个门控标量**，
   相对 106 M 参数可忽略（0.005%）。这点对论文的"不增加容量"论述有利。
