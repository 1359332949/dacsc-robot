## 第 0 部分：先回答"我们就按他的 backbone"

**可以，但要说清楚代价。** 这里有一个必须先讲清的矛盾：

| | CoRP 的 backbone | 我们原来的 backbone |
|---|---|---|
| 是什么 | **DINOv2 预训练的 ViT-S/14** | **ResNet18**（从零 / ImageNet） |
| "通道"是什么 | 每个 token 的 384 维隐藏向量 | 64/128/256/512 张空间特征图 |
| 预训练来源 | DINOv2（自监督，海量图片） | 无 / ImageNet |
| 我们的方法适配度 | 需要重新定义"通道" | **天生适配**（DomainDrop/PLACE/RoboSaGA 都在这一层） |

**关键矛盾**：我们的方法核心是"**按通道做域敏感性门控**"。
在 **ResNet18** 上，"通道" = 一张空间特征图（比如"专门抓木纹的那个特征图"），语义非常清晰，直接关掉就行。
在 **DINOv2 ViT** 上，"通道" = token 的隐藏维度，"关掉某个维度"是否等价于"关掉某种特征"，**需要先验证**。

**所以我的建议是"双 backbone"，而不是只换成他的：**

```
L1   主实验：DP + ResNet18（从零 / ImageNet / R3M）
     → 方法的主场，通道语义清晰，能做全部消融
     → 也是官方 RoboCasa DP fork 的原生配置（改动最小）

L1b  对照实验：把视觉编码器换成 DINOv2 ViT-S/14
     → 对齐 CoRP，直接可比
     → 同时回应 4.3 的发现"预训练是关键"
     → 顺便验证"我们的通道门控在 ViT 上是否同样有效"
```

**代价**：我们的 DP fork 里视觉部分是 robomimic 的 `ResNet18ConvFiLM`（写死的）。
换成 ViT 需要**重新实现一个 obs encoder**——估计 **1–2 天**的工程量，但没有理论障碍。

**收益**：L1b 一旦做成，我们就能说"我们的方法在 ResNet 和 ViT 上都有效"，这比只说 ResNet 强得多。

## 第 1 部分：LIBERO 是什么，那张表怎么读

### LIBERO 是什么

**一个机器人操作的标准测试集**（2024 年出的，现在是模仿学习领域用得最多的基准 —— 前面统计过，2026 年有 725 篇论文用它）。

它包含 **4 个套件（suite）**，每个套件 10 个任务：

| 套件 | 名字的意思 | 测什么 |
|---|---|---|
| **Spatial** | 空间 | 物体位置变了，能不能适应 |
| **Object** | 物体 | 换成同类但不同的物体（杯子换成另一个杯子） |
| **Goal** | 目标 | **同一个场景下，指令不同 → 目标不同** |
| **Long** | 长时序 | 需要连续做很多步 |

**注意 Goal 套件的特殊性**：场景长一样，但"把杯子放抽屉"和"把杯子放水槽"是不同任务。**光看图分不出该做哪个 —— 必须读指令。** 这就是为什么 4.5 那个"语言条件"消融在 Goal 上会崩到 9.2%。

### 那张表的三列到底在说什么

| 列 | 是什么 | 怎么理解 |
|---|---|---|
| **Method** | 方法名字 | — |
| **Params (B)** | **参数量，单位是 B = billion = 10 亿** | 0.049B = 4900 万；3.3B = 33 亿。**越小越好**（同样的成绩，谁小谁强） |
| **Spatial/Object/Goal/Long/Avg** | **成功率（%）** | 每个套件里，机器人把任务做完的比例。**Avg = 四个套件的平均** |

**读表的正确姿势**：看"**每单位参数的成绩**"。

举例：

```
π0.5        :  3.3B  → 96.9%     每 10 亿参数换 29 分
CoRP (L=3)  :  0.063B → 98.4%    每 10 亿参数换 1562 分  ← 效率高 50 倍
DP          :  0.157B → 72.4%    每 10 亿参数换 461 分
```

**为什么这张表对我们是好消息**：它证明**参数少可以赢**，而且**赢的关键在"看得好不好"**（这就是我们做的那一层）。

### 为什么用 LIBERO 做"受控对比"

论文原话：

> "Its evaluation follows the demonstration distribution, so we use it for **controlled comparisons** (Sections 4.3–4.6), where differences reflect **representation rather than robustness**."

**翻译**：LIBERO 的测试场景和训练场景**几乎一样**（不换装修、不换灯光）。
所以在这里比较，**比的是"表示学得好不好"，而不是"抗不抗环境变化"**。

**这句话非常重要**，它说明论文作者的实验纪律：
- **LIBERO 用来比"表示质量"**（因为环境不变，差异只能来自表示）
- **RoboTwin Randomized 用来比"抗环境变化"**（因为环境会变）

**我们要学的就是这个纪律**：
- 我们的"表示质量"实验应该在环境不变的设定下做
- 我们的"抗环境变化"实验必须在环境变化的设定下做
- **不能混**，否则归因不清

## 第 2 部分：Randomized 是什么，为什么它是全篇最重要的一格

### RoboTwin 2.0 是什么

**另一个机器人操作基准**（双臂机器人 Aloha，50 个任务），由 RoboTwin 团队维护（我们本地有 `repos/RoboTwin`）。
它有**两种场景设置**：

| 设置 | 场景 | 含义 |
|---|---|---|
| **Clean** | 干净的、单一风格的场景 | 和训练时一样 |
| **Randomized** | **随机化场景**：背景纹理、灯光、桌面高度、杂物位置都会变 | 环境会变 |

**RoboTwin 的随机化包含**（来自我们本地源码 `_base_task.py`）：
```yaml
random_background: true       # 墙面/桌面纹理随机
random_light: true            # 灯光随机
random_table_height: 0.03     # 桌面高度随机
cluttered_table: true         # 桌上放杂物
```

### ⚠️ 一个极其重要的细节

论文特意加了一句：

> "following Bi et al. (2026), we train on **2,500 clean and 25,000 randomized demonstrations**, so **Randomized tests in-distribution visual variation rather than zero-shot transfer**."

**翻译**：**训练时就给模型看了 25000 条随机化场景的数据！**

所以 Randomized 这一列**不是零样本测试**（不是"训练时没见过、测试时第一次见"），而是"**训练时见过这类变化，测试时再看一次**"。

**这为什么极其重要**：
1. **这是最宽松的测试**——模型已经见过随机化了
2. **就在这么宽松的测试下，DP 还是崩到 0.6%**
3. **这说明 DP 的问题不是"没见过"，而是"根本学不会处理变化"**

**对我们的意义**：我们的任务（外观域泛化）本质上更难 —— 我们测的是"**零样本**：训练时见过风格 A/B/C，测试时第一次见风格 D"。
DP 在**宽松设定**下都崩到 0.6%，那在**严格设定**（我们的设定）下只会更糟。
**这给我们的方法留了巨大的提升空间。**

### 这张表怎么读

| 方法 | Clean | **Randomized** | 掉了多少 |
|---|---|---|---|
| Motus (8B) | 88.7 | 87.0 | **-1.7** ✅ 最稳 |
| GigaWorld (11.4B) | 86.4 | 85.0 | -1.4 ✅ |
| **CoRP (0.049B)** | 75.8 | 73.4 | **-2.4** ✅ 极稳 |
| X-VLA (0.9B) | 72.9 | 72.8 | -0.1 ✅ |
| π0.5 (3.3B) | 43.0 | 43.8 | +0.8 |
| π0 (3.3B) | 46.4 | **16.3** | **-30.1** ❌ |
| ACT (0.084B) | 29.7 | **1.7** | **-28.0** ❌ |
| **DP (0.157B)** | 28.0 | **0.6** | **-27.4** ❌ |

**结论**：**有些方法几乎不掉，有些方法直接崩。而"崩不崩"和"参数大小"没关系**（π0 3.3B 掉了 30 分，CoRP 0.049B 只掉 2.4 分）。

**论文的推断**：
> "Diffusion Policy and ACT, whose visual encoders are learned **without a large-scale pretrained vision model**, collapse... **an early sign that the visual representation drives robustness**."

**翻译**：DP 和 ACT 崩了，它们的共同点是**视觉编码器没有用大规模预训练模型**。
所以**"抗不抗环境变化"取决于"视觉表示"**。

**这正是我们的选题依据。**

## 第 3 部分：四个消融，逐个讲

### 什么是"消融实验"（ablation）

**定义**：把方法里的某个部件**拆掉或换掉**，看成绩掉多少。

- 拆掉后成绩**大幅下降** → 说明这个部件**有用**
- 拆掉后成绩**没变** → 说明这个部件**没用**（论文里会承认）

**为什么必须做**：否则你说"我的方法好"，别人会问"**是你方法里的哪一部分好？会不会是其中某个不起眼的改动起作用？**"

**消融的黄金纪律**（CoRP 做得很标准）：

> "every variant uses the default configuration... and the same training recipe, **changing only the factor under study**"
>
> **翻译**：所有对比版本用完全一样的配置、完全一样的训练流程，**只改要研究的那个因素**。

### 消融 1（4.3）：预训练视觉编码器有用吗？

**问的问题**：成绩好是因为"用了 ViT"，还是因为"用了预训练"？

**为什么这个问题难回答**：因为有**两个因素同时变了**——架构（ViT vs ResNet）和预训练（有 vs 无）。
如果只比较"预训练 ViT"和"随机 ResNet"，你赢了也不知道是哪个因素的功劳。

**怎么解决 —— 2×2 交叉设计**：

把两个因素**交叉组合**，得到 4 个变体，而且**参数匹配**（22.1M vs 21.5M，几乎一样）：

| | 随机初始化 | 预训练 |
|---|---|---|
| **ViT-S/14** | 78.1% | **97.0%** ← DINOv2 |
| **ResNet-34** | 82.1% | **74.5%** ← ImageNet |

**这样一摆，结论就清楚了**：
1. 单看"架构"：随机时 ViT(78.1) **还不如** ResNet(82.1) → **架构本身不带来优势**
2. 单看"预训练"：ResNet 加了 ImageNet 预训练**反而变差**(74.5 vs 82.1) → **预训练本身也不保证优势**
3. **只有"预训练 + ViT"这个组合**才爆发 → **两者必须配合**

**这是全篇最漂亮的设计。** 用 4 个格子就把三个因素（架构、预训练、以及两者的交互）分离清楚了。

**我们要学的**：我们的门控也有两个因素（门控本身、域标签）。**我们也要用交叉设计**，否则说不清是哪个起作用。

### 消融 2（4.4）：只预训练不微调够吗？

**问的问题**：DINOv2 是海量数据训出来的，**直接冻住用它**（只训后面的）行不行？

**怎么设计**：两个版本，其他完全一样
- **Frozen**：视觉编码器锁死，只训后面的 resampler + 动作头
- **Fine-tuned**：视觉编码器也一起训

**结果**：

| | 成功率 | R²（后面解释） |
|---|---|---|
| Frozen | **77.2%** | 0.24 |
| Fine-tuned | **97.0%** | 0.81 |

**掉了 19.8 分。而且冻结版(77.2%)和"随机初始化从头训"(78.1%)几乎一样。**

**论文的解释**：
> "frozen features retain **much less action-relevant detail**"
> **翻译**：冻住的特征里，"与动作有关的信息"少得多。

**⚠️ 这条直接否定了我之前给你的一个建议**（"冻住视觉部分、只装开关"）——因为**冻住的特征本身就不够好**。

**对我们的意义**：L2 迁移实验**必须**做"微调 + 门控"，不能只做"冻结 + 门控"。

### 消融 3（4.5）：需要语言条件吗？

**问的问题**：把语言指令去掉，会怎样？

**背景**：机器人接到的输入除了图像，还有一句指令（"把杯子放进抽屉"）。
他们的方法把指令**注入到视觉压缩的 query 里**（一种叫 FiLM 的调制方式）。

**结果分两种情况 —— 这是最有意思的部分**：

| | 有语言 | 无语言 | 变化 |
|---|---|---|---|
| LIBERO-Spatial | 98.2 | 87.0 | -11.2 |
| LIBERO-Object | 99.4 | 100.0 | +0.6 |
| **LIBERO-Goal** | **95.8** | **9.2** | **-86.6** 🔴 |
| LIBERO-Long | 94.4 | 83.4 | -11.0 |
| **RoboTwin Clean** | 75.78 | **78.50** | **+2.7** ⬆️ |
| **RoboTwin Rand.** | 73.36 | **76.06** | **+2.7** ⬆️ |

**为什么 Goal 上崩掉，RoboTwin 上去掉语言反而变好？**

论文给了一个清晰的判据：**只有"看图分不出该做哪个任务"时，语言才有用。**

- **LIBERO-Goal**：同一个场景对应多个目标（杯子可以放抽屉、也可以放水槽）→ **看图分不出** → 必须读指令 → 去掉就崩
- **RoboTwin**：每个场景本身就确定了任务 → **看图就能分出** → 语言是多余的 → 去掉反而少了个干扰

**对我们的意义**：我们的 RoboCasa365 是**300 个任务的混合**，同一个厨房场景可能对应很多不同任务。
所以**语言应该是需要的**（类似 LIBERO-Goal 的情况）。
但我们**必须做这个消融**来证明——否则别人会问"你的提升会不会只是语言条件带来的"。

### 消融 4（4.6）：信息瓶颈有用吗？

**先解释什么是"信息瓶颈"**

机器人看图后会产生很多信息（他们这里是 256 个 token）。信息太多有两个问题：
- 慢（后面要处理很多）
- 容易学到没用的东西

所以想**压缩**。有两种压缩思路：

| 思路 | 怎么压 | 特点 |
|---|---|---|
| **VIB**（变分信息瓶颈） | 加一个惩罚项，"逼"所有信息都往同一个标准靠 | **任务无关**：不管你在做什么任务，都压成一样的 |
| **他们的方法**（resampler） | 用 48 个"提问者"，**按指令有选择地**去原文里抽取信息 | **任务感知**：你问什么，我就抽什么 |

**用"读报告"来类比**：
- **VIB** = 规定"所有人的报告都压到 1 页，且必须按同样的格式写" → 可能把关键内容也压掉了
- **他们的方法** = "你说你是财务部的，那我就只抽财务相关的部分给你" → **按需求裁剪**

**怎么设计 —— 又是 2×2 交叉**：

| | 不用 VIB | 用 VIB |
|---|---|---|
| **全用 256 个 token** | 83.2% | 77.8% ⬇️ |
| **压成 48 个 token** | **97.0%** ⬆️ | 75.9% ⬇️ |

**结论三条**：
1. **"压成 48 个"比"全用 256 个"好 +13.8 分** → 压缩有用
2. **但 VIB 无论怎么加都变差**（83.2→77.8，97.0→75.9）→ **VIB 这种压缩方式不行**
3. **原因**：VIB 是**任务无关**的（把所有 token 压向同一个先验），而 resampler 是**任务感知**的

**🔑 这条对我们是最有价值的背书**：

> **"盲目压缩"不行，"按语义信号有选择地压缩"才行。**

**我们的方法正是"按域标签有选择地抑制通道"，而不是"无差别随机抑制"（比如普通 Dropout）。**
逻辑完全同构 —— 所以我们的**必做对比实验**是：

```
我们的域感知门控   vs   随机 Dropout（无差别抑制）
```

如果前者赢，就直接呼应了 CoRP 的这条发现。

## 第 4 部分：指标词典（含那两个"体检分数"）

### 基础指标

| 指标 | 全称 | 含义 | 越大越好？ |
|---|---|---|---|
| **Params (B)** | Parameters (Billion) | 参数量，单位 10 亿。衡量"模型多大/多贵" | **越小越好** |
| **Success Rate (S.R.)** | — | **成功率**：任务完成的比例 | 越大越好 |
| **Acc.** | Accuracy | **任务识别准确率**：模型能不能认出这是哪个任务 | 越大越好 |

**为什么同时报 Acc. 和 S.R.？** —— 这个设计很聪明：

论文发现：**弱变体的 Acc. 是 100%，但 S.R. 只有 37%**。

**翻译**：**"它知道该做哪个任务，但手不听使唤。"**

这证明问题不在"理解任务"，而在"**看得不够细**"（缺乏细粒度的视觉信息去执行）。

**对我们的意义**：如果我们的方法提升了 S.R.，但 Acc. 没变，说明我们改善的正是"看得细不细"——**这才是我们想要的效果**。这个双指标我们也要报。

### 两个"体检分数"：NMAE 和 R²

这两个是**探针（probe）指标**，专门用来回答"**特征里到底还剩多少动作信息**"。

**先理解"探针"是什么意思**：

> 成功率只告诉你"最终好不好"，但**不告诉你为什么**。
> 探针就是：**从模型的中间特征里，能不能把动作猜回来？**
> 能猜回来 → 特征里保留了动作信息；猜不回来 → 信息丢了。

**NMAE**（Normalized Mean Absolute Error，归一化平均绝对误差）
- 做法：拿一个简单的小模型，试着从特征里"解码"出动作，算误差
- **越低越好**（误差小 = 特征里动作信息保留得好）

**R²**（决定系数，coefficient of determination）
- 做法：同样的解码实验，算"能解释动作变化的多大比例"
- 范围 0–1，**越高越好**（1 = 完全能解释，0 = 完全不能）

**看这两个数的实际用法**：

| 变体 | S.R. | NMAE | R² |
|---|---|---|---|
| 微调（默认） | 97.0% | 0.07 | **0.81** |
| 冻结 | 77.2% | 0.16 | **0.24** |

**读法**：冻结后 R² 从 0.81 → 0.24，说明**特征里能解释动作的信息掉了一大半**。
**这就解释了为什么成功率掉 20 分** —— 不是"没学好"，而是"**原料就不够了**"。

**为什么我们要学这个设计**：

成功率提升是"结果"，但审稿人会问"**你的门控到底改了什么？为什么能提升？**"

有了探针，我们就可以说：

> "我们的门控关闭了 30% 的通道，但 R² 只从 0.81 掉到 0.79 ——
> **说明我们关掉的主要是域相关而非动作相关的通道**。"

**这是机制证据，比成功率更有说服力。**

## 第 5 部分：总结 —— 我们对 CoRP 的"借鉴清单"

| 借鉴什么 | 具体怎么做 |
|---|---|
| **2×2 交叉消融** | 我们也要交叉：{有门控, 无门控} × {有域标签, 无域标签}（或"用真标签 vs 用随机标签"） |
| **特征探针 NMAE / R²** | 必做。证明"关门控后动作信息没被破坏" |
| **同时报 Acc. 和 S.R.** | 必做。区分"不会认任务"和"看得不够细" |
| **"只改一个因子"的纪律** | 所有对比版本用同一套超参、同一训练流程 |
| **双 benchmark 的分工** | 环境不变的设定比"表示质量"；环境变化的设定比"抗变化能力"。**不能混** |
| **域感知门控 vs 随机 Dropout** | 必做对比，呼应它的 4.6（任务感知 vs 任务无关） |
| **语言条件消融** | 必做。因为我们的 RoboCasa365 是 300 任务混合，语言可能很关键 |
| **"闭集评测"的局限写法** | 它承认不覆盖开放世界泛化 → 我们引用它来界定自己的贡献 |

### 我们要额外做、它没做的

| 做什么 | 为什么 |
|---|---|
| **从零训 ResNet18 vs R3M/ImageNet 预训练 ResNet18** | 回应它的 4.3（预训练关键），但我们的重点是"门控在哪种表示上更有效" |
| **DINOv2 ViT-S/14 版本（L1b）** | 与它直接可比 |
| **零样本域泛化**（我们自己的风格划分） | **它没做**，这是它的局限第一条 |
| **反事实对的一致性约束** | 它没有；这是我们的独有机制 |
