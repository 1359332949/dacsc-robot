# 84 - 动作接口预训练权重部分复用

日期：2026-11-05

## 1. 问题

官方 CoRP LIBERO checkpoint 的动作空间是 7D：

```text
end-effector position 3
+ end-effector rotation 3
+ gripper 1
```

RoboCasa 是 12D：

```text
end-effector position 3
+ end-effector rotation 3
+ gripper 1
+ base motion 4
+ control mode 1
```

前 7 维语义严格对齐。此前的加载器只按 tensor 总 shape 判断，因此把：

```text
action_projection.weight  [768,7] -> [768,12]
velocity_projection.weight [7,768] -> [12,768]
velocity_projection.bias   [7] -> [12]
```

整块随机初始化，丢失了官方 7D 动作头的预训练权重。

## 2. 实现

新增初始化策略：

```text
libero_shared_plus_aligned_7d_action_head_v1
```

规则：

```text
action_projection.weight[:, 0:7] = LIBERO weight
action_projection.weight[:, 7:12] = 0

velocity_projection.weight[0:7, :] = LIBERO weight
velocity_projection.weight[7:12, :] = 0

velocity_projection.bias[0:7] = LIBERO bias
velocity_projection.bias[7:12] = 0
```

`action_projection.bias` 形状本来就是 `[768]`，继续完整复用。

新增 5 维采用确定性零初始化：当 RoboCasa 新增动作维输入为 0 时，前 7 维动作 embedding
与官方 LIBERO 动作头一致；新增的 base motion / control mode 维由训练学习。

## 3. 保持随机的部分

仍随机初始化：

```text
representation_extractor.state_encoder.projection.weight [768,9]
```

原因：LIBERO 旋转是 axis-angle 3D，RoboCasa 是 quaternion 4D，不能安全逐通道对应。

第三视角 query / view embedding 仍按原规则：前两个视角映射复用，第三个随机。

## 4. 防止新旧结果混用

初始化策略会改变训练起点，因此：

```text
checkpoint format: corp_robocasa_v4 -> corp_robocasa_v5
SR protocol:       corp_robocasa_sr_v6 -> corp_robocasa_sr_v7
```

`initialization_policy` 写入：

- training checkpoint
- `result.json`
- SR training origin

旧 v4 checkpoint 和 v6 SR 结果拒绝加载，不能与新初始化结果同表。

## 5. 回归验证

必须验证：

- 前 7 维 action projection 与官方 checkpoint 逐元素一致
- 前 7 维 velocity row/bias 与官方 checkpoint 逐元素一致
- 新增 5 维严格为 0
- state projection 仍被标记为 random
- 第三视角仍随机
- `initialization_policy` 写入 checkpoint、result 和 evaluation origin

## 6. 证据边界

这是有明确维度和语义依据的初始化复用，不证明它一定提升成功率。

下一步必须在相同 batch/steps/task/episode 下重新训练 no-gate baseline，并与旧的
全随机动作接口 v4 结果分开比较；不能把旧 v4 结果当作新策略的直接对照混表。

## 7. 首次实测负结果（2026-11-05）

v5 对齐初始化从官方 LIBERO checkpoint 启动，配置与旧 v4 相同：

```text
batch 96
lr 5e-5
EMA 0.99
task_aux 0.01
seed 42
```

同一步数 flow loss：

| step | v4 全随机动作接口 | v5 前7维复用+新增5维置零 |
| ---: | ---: | ---: |
| 0 | 1.4463 | 0.9842 |
| 100 | 1.0930 | 0.7061 |
| 250 | 0.2775 | 0.5645 |
| 500 | 0.1793 | 0.5637 |
| 540 | 0.1641 | 0.5393 |

v5 在最初100步 loss 更低，但随后下降明显变慢，到250步以后显著差于全随机动作接口。
训练约550步后已停止，未继续浪费10k预算。

可能原因：

1. 官方 LIBERO 动作头接收的是 LIBERO min-max 归一化后的动作，而当前 RoboCasa
   使用 action identity；前7维虽然维度对应，输入/输出尺度不一定一致。
2. action projection 新增5列和 velocity projection 新增5行/ bias 全零，导致
   base motion / control mode 初期完全不参与，优化明显变慢。
3. 只复制部分输入和输出投影可能形成不一致的局部表示，不能仅凭维度相同认定可迁移。

结论：**“维度对齐”不等于“权重可直接复用”。当前 aligned-zero 版本不能作为
默认初始化继续训练。**

下一步应做短步数初始化消融，优先比较：

```text
全随机 12D 动作接口
前7维复用 + 新增5维随机初始化
前7维复用 + 新增5维零初始化
```

如果“新增5维随机”仍不如全随机，应放弃该复用处，而不是用更长训练掩盖初始化问题。

## 8. 最终决定（2026-11-05）

结合上游实现后，项目最终不采用任何动作头部分复制：

```text
checkpoint format: corp_robocasa_v5 -> corp_robocasa_v6
SR protocol:       corp_robocasa_sr_v7 -> corp_robocasa_sr_v8
initialization:    libero_shared_random_12d_action_interface_v1
```

保留：

- DINOv2
- T5
- resampler/FiLM
- DiT block、adaLN、time embedding
- 前两个 view query/view embedding

随机初始化：

- state projection `8 -> 9`
- action projection `7 -> 12`
- velocity projection `7 -> 12`
- 第三视角 query/view embedding

上游依据：

- OpenPI/LeRobot 使用固定最大动作维和零填充，前提是预训练动作头已经在该固定宽度上训练；
  不执行任意 shape 裁剪拼接。
- GR00T 对 `NEW_EMBODIMENT` 要求新 modality/normalization 配置并微调。
- RoboCasa 官方 DP 使用 action identity，而 CoRP LIBERO 使用 motion min-max；
  两者数值语义不同。

因此，CoRP-RoboCasa 的 12D action interface 必须重新训练，不能把 LIBERO 动作头
切片后直接复用。这个方案仍是 LIBERO 预训练权重上的微调，不是从随机模型从零训练。
